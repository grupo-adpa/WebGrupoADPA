# Aviso de dependencias reproducido el 17/11/2026

`npm audit --audit-level=moderate` falla por
[GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf),
ReDoS de picomatch mediante extglobs repetidos de una sola rama.
La ficha oficial, revisada/actualizada el 17/11/2026, indica versiones afectadas
hasta 4.0.7 y ninguna versión corregida. `npm view picomatch version` devuelve
4.0.7 en esta comprobación.

## Reproducción y alcance

- Base `main` de WebGrupoADPA: `00a3e6374e2d60a1b973cc9957200e5519b120df`.
- PR 3: mismo lockfile; su ejecución verde anterior fue
  [44013305546](https://github.com/grupo-adpa/WebGrupoADPA/actions/runs/44013305546).
- PR 4: no cambia dependencias ni `package-lock.json`.
- Se copiaron `package.json` y `package-lock.json` de `origin/main` a un
  directorio temporal y se ejecutó `npm audit --package-lock-only --json`.
  Se comparó con `npm audit --json` en PR 4.
- Ambos informes muestran 10 entradas de severidad alta: un aviso raíz en
  picomatch y sus dependientes. No son diez vulnerabilidades nuevas de InVue.
- Cadena instalada: `vite@8.3.8 → picomatch@4.0.7`; también
  `vite → tinyglobby@0.2.17 → fdir@6.5.0 → picomatch@4.0.7` y herramientas TS.
- La dependencia pertenece a la compilación. El contenedor final sirve archivos
  estáticos con Nginx y no incluye Node ni node_modules; esto no convierte el
  resultado de audit en aprobado.

## Decisión

No hay parche compatible publicado que aplicar. La sugerencia de
`npm audit fix --force` rebajaría Vite a 6.2.7, contra la versión fijada en el
brief. No se aplicó, no se ignoró el aviso ni se cambió el umbral.

En PR 4, audit es un job obligatorio independiente. Las pruebas visuales,
accesibilidad y Docker pueden completarse, pero el control `quality` exige
éxito tanto de audit como de las dos variantes. El PR sigue bloqueado por
seguridad hasta disponer de corrección compatible o de una decisión explícita
del responsable sobre el cambio de dependencias.
